This page gets you to one endpoint serving one view, tested in the app, by the shortest route. The protocol details are in Provider integration.

What you need: a backend reachable over HTTPS from a phone, Node 18+ or Python 3.10+, and a Yeria account.

1. Generate your keypair

The private key signs the views you return. It never leaves your server.

openssl genpkey -algorithm ed25519 -out service_private.pem
openssl pkey -in service_private.pem -pubout -out service_public.pem

The algorithm must be Ed25519. The registry rejects any other key.

2. Declare the service

In the provider space, create the service, fill in its base URL, and paste the contents of service_public.pem into the public key field.

Note the service id: it pins the audience of the user tokens you will receive.

3. Install the SDK

The package is named differently in each language but ships the same protocol version: @numerum-tech/yeriasdk for Node, yeriasdk for Python.

npm i @numerum-tech/yeriasdk
pip install yeriasdk

The install compiles nothing. Ed25519 signing uses each platform's standard library, so there is no native dependency to build.

4. Configure the backend

YERIA_BASE_URL=https://yeria.app
YERIA_APP_ID=your-application
YERIA_SERVICE_ID=your-service
SERVICE_ED25519_PRIVATE_KEY="$(cat service_private.pem)"

5. Return a view

The SDK splits two responsibilities: YeriaUI builds the view and holds no key; YeriaApp holds the key, signs the view and verifies inbound tokens.

import express from 'express';
import { YeriaUI, YeriaApp } from '@numerum-tech/yeriasdk';

const app = new YeriaApp({
  appId: process.env.YERIA_APP_ID,
  baseUrl: process.env.YERIA_BASE_URL,
  privateKey: process.env.SERVICE_ED25519_PRIVATE_KEY,
});

const server = express();

server.get('/topup', (req, res) => {
  const view = YeriaUI.createFormView('topup', 'Account top-up')
    .setIntro('Verified service · direct payment')
    .addPhoneField('msisdn', 'Number', true)
    .addNumberField('amount', 'Amount (FCFA)', true)
    .submitButton('Pay', 'POST');

  res.json(app.serve(view));
});

server.listen(8080);
import os
from fastapi import FastAPI
from yeriasdk import YeriaUI, YeriaApp, YeriaAppConfig

app = YeriaApp(YeriaAppConfig(
    app_id=os.environ["YERIA_APP_ID"],
    base_url=os.environ["YERIA_BASE_URL"],
    private_key=os.environ["SERVICE_ED25519_PRIVATE_KEY"],
))

server = FastAPI()

@server.get("/topup")
def topup():
    view = (
        YeriaUI.create_form_view("topup", "Account top-up")
        .set_intro("Verified service · direct payment")
        .add_phone_field("msisdn", "Number", True)
        .add_number_field("amount", "Amount (FCFA)", True)
        .submit_button("Pay", "POST")
    )
    return app.serve(view)

serve() returns the { payload, signature } envelope. The app verifies the signature with your public key before rendering the screen; a view it cannot verify is refused.

6. Verify the user token

The app calls your endpoint with a bearer token Yeria minted for your service. You verify it yourself. The SDK gives you helpers for that; it does not hand you a middleware.

const auth = req.headers.authorization || '';
const bearer = auth.toLowerCase().startsWith('bearer ') ? auth.slice(7).trim() : '';
const user = await app.verifyUserToken(bearer, process.env.YERIA_SERVICE_ID);

The platform signing key is fetched once and cached: later verifications make no network call.

7. Test

Your service is not in the catalogue yet. Until it has been through the Yeria review, and any time it is unpublished, it appears nowhere in search or in the public listings. You will find it in the app under My private services, and nowhere else.

That section only lists services you have been granted access to, so you have to invite yourself. Open your service in the provider area, go to the Access tab, and invite the account you use in the app. Accept the invitation when it arrives, and the service shows up in your private list with the view your backend serves.

Open your service from the Yeria app. The screen from step 5 appears natively. Change the view, redeploy, then reopen the service: the screen changes without shipping a new app version.
