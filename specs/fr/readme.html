Référence du SDK Yeria, disponible pour JavaScript/TypeScript (@numerum-tech/yeriasdk) et Python (yeriasdk). Les deux implémentations signent de façon byte-identique : une vue construite dans l'une se vérifie dans l'autre.

Chaque spécification de composant contient :

  • Description du composant : rôle, cas d'usage et principes de conception
  • Tableau des champs : référence complète avec types, exigences et descriptions
  • Exemples de code : cas concrets d'utilisation du composant

Par où commencer

  • Intégration provider — de bout en bout : générer votre paire de clés Ed25519, l'enregistrer, vérifier les jetons utilisateurs entrants, récupérer les profils. À lire en premier.
  • YeriaUI & YeriaApp — les deux points d'entrée du SDK. YeriaUI construit les vues (sans clé) ; YeriaApp détient votre clé et signe.
  • Navigation — le chemin entre vos écrans : sur quoi retombe le geste de retour, quand un résultat remplace le formulaire qui l'a produit, et comment se pilote une séquence paginée. Recense aussi ce que les clients n'honorent PAS.

Les vues disponibles

Formulaires

  • FormView — formulaires dynamiques : types de champs variés, règles de validation, action de soumission. Gère le texte, l'e-mail, le mot de passe, les nombres, les dates, les listes déroulantes, l'envoi de fichiers, les coordonnées GPS et davantage.

Affichage de contenu

  • ReaderView — affichage de contenu riche destiné à la lecture. Gère les paragraphes, images, contenus Markdown, listes, liens, tableaux, blocs de code, citations et éléments personnalisés.
  • CardView — fiche compacte mettant en avant un élément unique, avec statistiques, sections et actions. Adaptée à une fiche produit, un profil utilisateur ou le détail d'un événement.
  • CarouselView — carrousel pour mettre en avant un contenu, une annonce ou une promotion. Gère le défilement automatique, la boucle et des réglages d'affichage.
  • TimelineView — frise chronologique pour suivre une progression, des étapes d'inscription ou un fil d'activité. Gère les indicateurs d'état (en attente, actif, terminé, erreur).
  • MediaView — lecteur audio et vidéo avec liste de lecture. Gère plusieurs sources, les affiches et les contrôles de lecture.
  • MapView — carte géographique avec marqueurs, cadrage, contrôles et surcouches. Le backend fournit les données, le moteur de rendu gère le style et les interactions.

Actions

  • ActionListView — liste verticale d'actions pour un menu de navigation, une liste de fonctionnalités ou un centre de commandes. Chaque action peut porter un titre, une description, une vignette et des métadonnées.
  • ActionGridView — grille d'actions pour un tableau de bord ou une navigation par icônes. Nombre de colonnes (1 à 6) et espacement configurables.
  • IconGridView — grille d'icônes compacte, pour une navigation dense où l'icône prime.

Codes QR

  • QRScanView — interface de scan de code QR. L'application mobile implémente le scanner ; la vue décrit quoi scanner et où soumettre. Gère la soumission automatique, la validation et les modes d'aperçu.
  • QRDisplayView — affichage de codes QR pour partager un code d'accès, un billet ou une information de paiement. Gère plusieurs codes, chacun avec son titre, sa description et ses options.

Messages

  • MessageView — affichage de message, notification ou alerte. Gère les niveaux de gravité (information, succès, avertissement, erreur) avec une action principale et une action secondaire. Peut être fermable ou exiger une réponse de l'utilisateur.

Texte d'en-tête

Chaque vue porte une courte ligne de contexte sous son titre, posée par setIntro(texte) et portée par la clé intro. CardView y ajoute setDescription(texte) pour son paragraphe de corps, qui est un autre rôle. Sur CardView et CarouselView la clé s'appelait subtitle : setSubtitle(texte) est conservé comme alias de setIntro et écrit la même clé. Tous les textes d'en-tête suivent le même contrat :

  • Le texte est détouré, et une valeur vide ou blanche est refusée par une InvalidParameterError. Une ligne d'en-tête se pose ou n'existe pas : il n'y a pas d'état « vide ».
  • Un setter jamais appelé n'émet aucune clé. Le client ne dessine rien pour une clé qu'il ne reçoit pas : une intro non posée ne coûte aucune hauteur.

Démarrage rapide

Construire une vue ne demande aucune clé ; la signer, si. C'est pourquoi les deux étapes vivent sur deux objets distincts.

import { YeriaUI, YeriaApp } from '@numerum-tech/yeriasdk';

// Détient votre clé privée Ed25519 — signe, vérifie, dialogue avec Yeria.
const app = new YeriaApp({
    appId: 'my-app',
    baseUrl: process.env.YERIA_BASE_URL,
    privateKey: process.env.SERVICE_ED25519_PRIVATE_KEY,
});

// Fabrique sans clé — jamais instanciée, utilisée comme Math ou JSON.
const form = YeriaUI.createFormView('registration', 'User Registration')
    .addTextField('name', 'Name', true)
    .submitButton('Register', 'POST');

// Signature en enveloppe v3 : { payload, signature }
res.json(app.serve(form));

En Python, même protocole :

from yeriasdk import YeriaApp, YeriaAppConfig, YeriaUI

app = YeriaApp(YeriaAppConfig(
    app_id="my-app",
    base_url=os.environ["YERIA_BASE_URL"],
    private_key=os.environ["SERVICE_ED25519_PRIVATE_KEY"],
))

form = (YeriaUI.create_form_view("registration", "User Registration")
        .add_text_field("name", "Name", True)
        .submit_button("Register", "POST"))

envelope = app.serve(form)
